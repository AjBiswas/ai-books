AI Coding AssistantsAI Coding Assistants

This book was written with an AI coding assistant. So were its labs. In two years, coding assistants went from suggesting the next line to reading a whole codebase, running tests, fixing failures and opening pull requests. Using them well is now part of every software job, and an AI engineer is expected to be excellent at it, and to know where they go wrong.

Yeh book AI coding assistant ke saath likhi gayi. Iske labs bhi. Do saal mein coding assistants agli line sujhaane se poora codebase padhne, tests chalaane, failures theek karne aur pull requests kholne tak pahunch gaye. Inhe achhe se use karna ab har software job ka hissa hai, aur AI engineer se ummeed hai ki woh isme behtareen ho, aur jaane ki yeh kahan galat hote hain.

Vibe coding vs spec-drivenVibe coding vs spec-driven

"Vibe coding" (a term from Andrej Karpathy, 2025) means describing what you want, accepting whatever the AI writes, and fixing by asking again, without really reading the code. It's magical for prototypes and weekend projects. For anything others depend on, teams use spec-driven development: write down what to build, let the AI plan and implement against tests, and review every change.

"Vibe coding" (Andrej Karpathy ka 2025 ka shabd) matlab jo chahiye bata do, AI jo likhe maan lo, aur dobara poochkar theek karo, code ko sach mein padhe bina. Prototypes aur weekend projects ke liye jaadu hai. Jis par doosre nirbhar hon, uske liye teams spec-driven development use karti hain: kya banana hai likho, AI ko tests ke against plan aur implement karne do, aur har badlaav review karo.

Engineer's note

Give the assistant a project memory fileAssistant ko project memory file do

Coding agents read a file at the repository root: CLAUDE.md for Claude Code, AGENTS.md for many other tools. Put in it what a new teammate needs: how to run tests, coding conventions, folders not to touch, and gotchas. It's context engineering (Chapter 10) for your codebase. Keep it short and current; a stale memory file misleads every session.

Coding agents repository root par ek file padhte hain: Claude Code ke liye CLAUDE.md, kai doosre tools ke liye AGENTS.md. Isme woh rakho jo naye saathi ko chahiye: tests kaise chalaayein, coding niyam, kin folders ko na chhoona, aur jhol. Yeh aapke codebase ke liye context engineering (Chapter 10) hai. Chhoti aur taaza rakho; purani memory file har session ko bhatkaati hai.

AI behaviour

Confident, plausible, sometimes wrongYakeen bhara, vishwasniya, kabhi galat

Coding agents invent library functions that don't exist, "fix" a failing test by weakening it, quietly change unrelated files, and report "all tests pass" without running them. They also add security holes a human would spot (SQL built from strings, secrets in code). The counter-measures are the same as for any agent: tests they can't edit, small diffs, and a human reading the diff.

Coding agents na hone wale library functions bana lete hain, fail test ko kamzor karke "theek" karte hain, bematlab files chupchaap badal dete hain, aur bina chalaaye "saare tests pass" report karte hain. Woh aise security chhed bhi jodte hain jo insaan pakad leta (strings se bana SQL, code mein secrets). Ilaaj kisi bhi agent jaisa: aise tests jinhe woh badal na sakein, chhote diffs, aur diff padhta hua insaan.

In the real world

Agents with a shell need rulesShell wale agents ko niyam chahiye

An agentic assistant can run commands on your machine or CI. Companies set permission modes (ask before running commands, or allow only listed ones), block pushes to protected branches, keep secrets out of the agent's environment, and run autonomous jobs in disposable containers. Book 2, Chapter 10 shows hooks that enforce these.

Agentic assistant aapki machine ya CI par commands chala sakta hai. Companies permission modes lagaati hain (commands se pehle poochho, ya sirf listed allow), protected branches par push rokti hain, agent ke environment se secrets door rakhti hain, aur autonomous jobs disposable containers mein chalaati hain. Book 2 ka Chapter 10 aise hooks dikhata hai jo yeh laagu karte hain.

What we learnedHumne kya seekha

  1. Coding assistants went from autocomplete to agents that run tests and open PRs.
  2. Vibe-code prototypes; spec-drive anything others depend on.
  3. Plan first, keep diffs small, protect the tests, read every diff.
  4. Give the agent a project memory file and clear permission rules.
  1. Coding assistants autocomplete se tests chalaane aur PR kholne wale agents ban gaye.
  2. Prototypes vibe-code karo; jis par doosre nirbhar hon use spec-drive karo.
  3. Pehle plan, chhote diffs, tests surakshit, har diff padho.
  4. Agent ko project memory file aur saaf permission niyam do.
