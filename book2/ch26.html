EvalsEvals

"I tried it a few times and it looks good" is how most AI projects fail in production. Haron's answers vary from run to run, users ask in endless ways, and a change that improves one case can quietly break another. Evals are automated exams: a fixed set of realistic cases, a way to score each answer, and numbers you trust enough to decide whether a change ships. If you learn one production skill from this book, make it this one.

"Maine kuch baar try kiya, achha lag raha hai" aise hi zyaadatar AI projects production mein fail hote hain. Haron ke jawab har run mein badalte hain, users anginat tareekon se poochte hain, aur jo badlaav ek case sudhaare woh chupchaap doosra tod sakta hai. Evals automated exams hain: asli jaise cases ka tay set, har jawab ko score karne ka tareeka, aur aise numbers jin par itna bharosa ho ki tay kar sako badlaav ship hoga ya nahi. Is book se ek production skill seekho toh yeh seekho.

RememberYaad rakho

Report every score with an error bar, compare versions case by case, and always look at slices (language, customer type, product). An average can rise while the people who matter most get a worse product.

Har score error bar ke saath batao, versions case-by-case compare karo, aur hamesha slices dekho (bhasha, customer type, product). Average badh sakta hai jabki sabse zaroori logon ko kharab product mile.

AI behaviour

AI judges have biasesAI judges ke bias hote hain

When a model grades answers, it tends to prefer longer answers, the first option shown, and text written in its own style. Give it a clear rubric and a reference answer, grade one answer at a time, swap orders when comparing, and check its grades against 50–100 human-graded cases before trusting it.

Jab model jawab grade karta hai, woh aksar lambe jawab, pehla dikhaaya option, aur apne style mein likha text pasand karta hai. Use saaf rubric aur reference answer do, ek baar mein ek jawab grade karwao, compare karte waqt order badlo, aur bharosa karne se pehle uske grades 50–100 insaani-grade cases se check karo.

Engineer's note

Start tiny, grow from failuresChhota shuru karo, failures se badhao

Twenty well-chosen cases on day one beat a perfect plan for 2,000. Then every bug report, thumbs-down and production failure becomes a new case. Run the suite on every prompt, model or tool change (in CI), and nightly against production models, because providers update them.

Pehle din ke bees achhe chune cases 2,000 ke perfect plan se behtar. Phir har bug report, thumbs-down aur production failure naya case banta hai. Har prompt, model ya tool badlaav par suite chalao (CI mein), aur har raat production models par, kyunki providers unhe update karte hain.

In the real world

Evals for agentsAgents ke liye evals

For agents, grade the outcome (is the refund issued exactly once? do the tests pass?) and the trajectory (did it use the right tools, in a sensible order, without forbidden actions?), plus cost and steps per task. Because agents vary run to run, run each case several times and report how often it succeeds (pass@k, pass^k).

Agents ke liye nateeja grade karo (kya refund bilkul ek baar hua? tests pass hue?) aur raasta (kya sahi tools, samajhdaar order mein, bina mana kiye kaamon ke use kiye?), aur har kaam ka kharch aur steps. Agents har run mein alag hote hain, isliye har case kai baar chalao aur batao kitni baar safal hua (pass@k, pass^k).

For coders: a minimal eval runnerCoders ke liye: chhota eval runnerpython 
cases = [{"id": "t001", "input": "refund kab aayega?", "expect": "7 days", "lang": "hinglish"}, ...]

def run_suite(system, scorer):
    scores = {c["id"]: scorer(c, system(c["input"])) for c in cases}
    mean = sum(scores.values()) / len(scores)
    return scores, mean

contains = lambda case, out: float(case["expect"].lower() in out.lower())

What we learnedHumne kya seekha

  1. An eval is cases + a scorer + a report, run on every change.
  2. Grade with code where you can, a calibrated AI judge where you can't, and humans to check both.
  3. Error bars and slices stop you shipping lucky or harmful changes.
  4. For agents, grade the outcome, the path and the cost.
  1. Eval = cases + scorer + report, har badlaav par chalao.
  2. Jahan ho sake code se grade, jahan nahi wahan calibrated AI judge, aur dono ko check karne ke liye insaan.
  3. Error bars aur slices aapko kismat wale ya nuksaan wale badlaav ship karne se rokte hain.
  4. Agents ke liye nateeja, raasta aur kharch grade karo.
