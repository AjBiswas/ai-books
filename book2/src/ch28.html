Launch day is the beginning, not the end. Real users ask things nobody tested, providers quietly update models, a prompt tweak meant for one customer breaks another, and the bill doubles because an agent started looping. LLMOps is the practice of running AI apps in production: versioning prompts like code, tracing every request, watching quality, cost and drift, and turning every failure into a test.

Launch ka din shuruaat hai, ant nahi. Asli users aisi cheezein poochte hain jo kisi ne test nahi ki, providers chupchaap models update karte hain, ek customer ke liye kiya prompt badlaav doosre ko tod deta hai, aur bill double ho jaata hai kyunki ek agent loop karne laga. LLMOps production mein AI apps chalaane ka tareeka hai: prompts ko code ki tarah version karna, har request trace karna, quality, kharch aur drift par nazar, aur har failure ko test banana.

A trace: one request's storyTrace: ek request ki kahani

A trace records everything that happened for one request, as nested steps (spans): each model call with its prompt version, model, tokens, cost and time; each tool call with its input and result. When a user complains, the trace tells you exactly what Haron saw and did.

Trace ek request ke liye hua sab kuch record karta hai, nested steps (spans) ki tarah: har model call apne prompt version, model, tokens, kharch aur samay ke saath; har tool call apne input aur result ke saath. Jab user shikaayat kare, trace bilkul batata hai Haron ne kya dekha aur kiya.

AI behaviour

AI fails quietlyAI chupchaap fail hota hai

Normal software crashes loudly. AI usually fails politely: a fluent wrong answer, an extra loop, a reasonable-sounding refusal, answers that slowly get longer after a model update. Watch behaviour signals (thumbs-down rate, refusal rate, steps per task, answer length, a judge score on a sample of live traffic), not just errors and latency.

Aam software zor se crash hota hai. AI aksar vinamrata se fail hota hai: saaf galat jawab, extra loop, samajhdaar lagta inkaar, model update ke baad dheere-dheere lambe hote jawab. Sirf errors aur latency nahi, behaviour signals dekho (thumbs-down rate, refusal rate, har kaam ke steps, jawab ki lambaai, live traffic ke sample par judge score).

Engineer's note

Version everything that changes behaviourBehaviour badalne wali har cheez version karo

Prompt text, model ID (pin a dated or fixed version where the provider offers one), tool definitions, retrieval settings and temperature or effort are all part of "the model" your users experience. Store them in Git or a prompt registry, record the version in every trace, and change them only through a reviewed release with an eval gate and a quick rollback.

Prompt text, model ID (jahan provider de wahan fixed version pin karo), tool definitions, retrieval settings aur temperature ya effort, sab us "model" ka hissa hain jo users anubhav karte hain. Inhe Git ya prompt registry mein rakho, har trace mein version record karo, aur sirf eval gate aur jaldi rollback wali reviewed release se badlo.

In the real world

Tools you'll meetTools jo milenge

LLM observability platforms such as Langfuse, LangSmith, Arize Phoenix, Helicone and others store traces, prompts, datasets and eval runs; most accept OpenTelemetry data, which now has standard gen_ai.* attribute names. Pick one that can be self-hosted if prompts contain sensitive data, and don't log raw personal data by default.

Langfuse, LangSmith, Arize Phoenix, Helicone aur doosre LLM observability platforms traces, prompts, datasets aur eval runs rakhte hain; zyaadatar OpenTelemetry data lete hain, jiske ab standard gen_ai.* attribute names hain. Agar prompts mein sensitive data ho toh self-host ho sakne wala chuno, aur default mein raw personal data log mat karo.

  2. Trace every request with versions, tokens, cost and tool calls.
  3. Watch behaviour signals, not just errors.
  4. Version prompts and models like code, with gates and rollbacks.
  1. Production ek loop hai: ship, trace, nazar, failures jama, theek, dobara test.
  2. Har request versions, tokens, kharch aur tool calls ke saath trace karo.
  3. Sirf errors nahi, behaviour signals dekho.
  4. Prompts aur models code ki tarah version karo, gates aur rollbacks ke saath.
