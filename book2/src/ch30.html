Users never see your prompts, retrieval or agent loop. They see a screen. A brilliant agent behind a confusing interface feels broken; an average model behind a thoughtful interface feels magical. AI front-ends have their own patterns: text that streams in, answers that cite sources, a stop button, approval cards before risky actions, and sometimes interfaces the model builds on the fly.

Users aapke prompts, retrieval ya agent loop kabhi nahi dekhte. Woh screen dekhte hain. Uljhe interface ke peeche shaandaar agent toota lagta hai; soch-samajh kar bane interface ke peeche aam model jaadu lagta hai. AI front-ends ke apne patterns hain: dheere-dheere aata text, sources cite karte jawab, stop button, risky kaam se pehle approval cards, aur kabhi model ka turant banaaya interface.

RememberYaad rakho

Never call a model API directly from the browser with your API key: anyone can read it in the page source. The browser talks to your backend, which holds the key, checks the user, applies limits and streams the answer back.

Browser se seedhe apni API key ke saath model API kabhi call mat karo: koi bhi page source mein padh sakta hai. Browser aapke backend se baat karta hai, jiske paas key hai, jo user check karta hai, limits lagaata hai aur jawab wapas stream karta hai.

When the answer is an interfaceJab jawab hi interface ho

Not every answer should be a paragraph. With generative UI, the model calls a "show component" tool, and your front-end renders a real component (a flight card, a chart, a form) with the data. And before a risky action, the agent shows an approval card instead of acting: the human stays in the loop.

Har jawab paragraph nahi hona chahiye. Generative UI mein model "component dikhao" tool call karta hai, aur aapka front-end data ke saath asli component render karta hai (flight card, chart, form). Aur risky kaam se pehle agent kaam karne ki jagah approval card dikhata hai: insaan loop mein rehta hai.

AI behaviour

Markdown, links and images from the model are untrustedModel ka markdown, links aur images anjaan hain

Models write markdown, and the page renders it. A prompt-injected model can write an image link whose URL carries private data to an attacker's server the moment the page loads it, or a link that looks harmless but isn't. Sanitise model output, don't auto-load images from unknown domains, and never render raw HTML from the model.

Models markdown likhte hain, aur page use render karta hai. Prompt-injected model aisa image link likh sakta hai jiska URL page load karte hi private data hamlawar ke server tak le jaaye, ya aisa link jo bekhatar lage par ho nahi. Model output sanitise karo, anjaan domains ki images auto-load mat karo, aur model ka raw HTML kabhi render mat karo.

Engineer's note

Tools for building AI front-endsAI front-ends banaane ke tools

For prototypes and internal tools: Streamlit, Gradio or Chainlit give you a chat UI in a few lines of Python. For production web apps: frameworks like the Vercel AI SDK or assistant-ui handle streaming, tool-call rendering and message state in React. Under the hood it's usually Server-Sent Events from your backend.

Prototypes aur internal tools ke liye: Streamlit, Gradio ya Chainlit Python ki kuch lines mein chat UI dete hain. Production web apps ke liye: Vercel AI SDK ya assistant-ui jaise frameworks React mein streaming, tool-call rendering aur message state sambhaalte hain. Andar se aksar aapke backend se Server-Sent Events hote hain.

In the real world

Design for India's networks and languagesIndia ke networks aur bhashaon ke liye design

Many users are on mid-range phones and patchy 4G. Keep the page light, stream text (not heavy widgets), handle dropped connections by resuming, offer voice input, and let users switch language easily. Always label AI-generated content and give an easy way to reach a human.

Kai users mid-range phones aur kamzor 4G par hain. Page halka rakho, text stream karo (bhaari widgets nahi), toote connections ko resume karke sambhaalo, voice input do, aur bhasha aasaani se badalne do. AI-generated content ko hamesha label karo aur insaan tak pahunchne ka aasaan raasta do.

For coders: a streaming endpointCoders ke liye: streaming endpointpython · FastAPI 
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
import anthropic, json

app = FastAPI()
client = anthropic.Anthropic()          # key lives on the server only

@app.post("/chat")
def chat(body: dict):
    def events():
        with client.messages.stream(model="claude-opus-5-5", max_tokens=1024,
                                    messages=body["messages"]) as stream:
            for text in stream.text_stream:
                yield f"data: {json.dumps({'text': text})}\n\n"     # Server-Sent Events
        yield "data: [DONE]\n\n"
    return StreamingResponse(events(), media_type="text/event-stream")

Add authentication, per-user rate limits and input checks before the stream starts; in the browser, read the stream with fetch and append each chunk to the message.

Stream shuru hone se pehle authentication, har user ki rate limits aur input checks jodo; browser mein fetch se stream padho aur har tukda message mein jodo.

What we learnedHumne kya seekha

  1. Browser → your backend → model; the key never reaches the browser.
  2. Stream text, show progress, offer stop, retry and feedback.
  3. Cite sources, label AI content, and make the human route easy.
  4. Render rich components and approval cards; sanitise everything the model writes.
  1. Browser → aapka backend → model; key kabhi browser tak nahi pahunchti.
  2. Text stream karo, progress dikhao, stop, retry aur feedback do.
  3. Sources cite karo, AI content label karo, aur insaan tak pahunchna aasaan banao.
  4. Rich components aur approval cards render karo; model ka likha sab sanitise karo.
