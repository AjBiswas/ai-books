Most prompts are tuned by hand: change a word, try two examples, "looks better", ship. That's guessing. Automatic prompt optimisation turns it into a search with a score. You provide a task, a small labelled dataset and a metric; a program tries many candidate instructions and example sets, scores each on held-out data, and keeps the best. DSPy, from Stanford, is the best-known library for this. This chapter builds the core idea from scratch so you can see exactly what such libraries do.

Zyaadatar prompts haath se tune hote hain: ek shabd badlo, do examples try karo, "behtar lagta hai", ship. Yeh andaaza hai. Automatic prompt optimisation ise score wali khoj bana deta hai. Aap kaam, chhota labelled dataset aur ek metric dete ho; program kai instructions aur example sets aazmaata hai, har ek ko alag rakhe data par score karta hai, aur sabse achha rakhta hai. Stanford ka DSPy iske liye sabse mashhoor library hai. Yeh chapter mool idea shunya se banata hai taaki dikhe ki aisi libraries asal mein kya karti hain.

A prompt is a setting you can searchPrompt ek setting hai jise khoja ja sakta hai

Look at a prompt the way Chapter 37 looked at weights: a set of knobs. The instruction wording is a knob. Which few-shot examples you include is a knob. Their order is a knob. You can't take gradients through words, but you can try candidates and keep what scores best, as long as you have a metric you trust (Ch 26). The same discipline applies as in training: choose on a dev set, then report on a test set you never looked at, or you'll fool yourself.

Prompt ko waise dekho jaise Chapter 37 ne weights ko dekha: knobs ka set. Instruction ke shabd ek knob. Kaunse few-shot examples shaamil karein, ek knob. Unka kram, ek knob. Shabdon par gradient nahi le sakte, par candidates aazma kar sabse achha score wala rakh sakte ho, bas ek bharosemand metric ho (Ch 26). Training wala hi anushaasan: dev set par chuno, phir aise test set par report karo jo kabhi nahi dekha, warna khud ko dhokha doge.

3

What DSPy addsDSPy kya jodta hai

DSPy changes how you write the program in the first place. Instead of prompt strings, you declare signatures ("message → category") and modules (predict, chain-of-thought, retrieve) and compose them like functions. Then an optimiser (DSPy calls them teleprompters) compiles the program against your metric: it can bootstrap few-shot examples from the model's own successful runs, and propose and test new instructions (the MIPRO family does both). When you switch models, you re-compile instead of re-tuning prompts by hand.

DSPy program likhne ka tareeka hi badal deta hai. Prompt strings ki jagah aap signatures ("message → category") aur modules (predict, chain-of-thought, retrieve) ghoshit karte ho aur unhe functions ki tarah jodte ho. Phir ek optimiser (DSPy inhe teleprompters kehta hai) program ko aapke metric ke khilaaf compile karta hai: woh model ke apne safal runs se few-shot examples bana sakta hai, aur naye instructions sujha kar test kar sakta hai (MIPRO parivaar dono karta hai). Model badlo toh prompts haath se dobara tune karne ki jagah dobara compile karo.

Engineer's note

When it's worth itKab faayde ka hai

Automatic optimisation pays off when the task is repeated thousands of times, you have (or can label) 50+ examples, and the metric is reliable. It also makes model switches cheap. It's overkill for a one-off prompt, and it can only be as good as your metric: optimise against a sloppy judge and you'll get a prompt that pleases the judge (Book 2, Ch 3). Always keep the human-readable final prompt in version control (Ch 41) and look at it.

Automatic optimisation tab faayde ka hai jab kaam hazaaron baar dohraaya jaaye, aapke paas 50+ examples hon (ya label kar sako), aur metric bharosemand ho. Yeh model badalna bhi sasta banata hai. Ek-baar ke prompt ke liye zyaada hai, aur yeh aapke metric jitna hi achha ho sakta hai: dheele judge par optimise karo toh judge ko khush karne wala prompt milega (Book 2, Ch 3). Aakhri, padhne laayak prompt hamesha version control mein rakho (Ch 41) aur use padho.

What we learnedHumne kya seekha

  1. Treat instructions and examples as settings to search, scored by a metric you trust.
  2. Choose on a dev set, report on an unseen test set.
  3. Even a small search over a few candidates replaces guessing with measurement.
  4. DSPy declares programs as signatures and modules, then compiles prompts against your metric.
  5. Worth it for repeated tasks with data; useless with a bad metric.
  1. Instructions aur examples ko khojne laayak settings maano, bharosemand metric se score.
  2. Dev set par chuno, anjaan test set par report karo.
  3. Kuch candidates ki chhoti khoj bhi andaaze ki jagah naap le aati hai.
  4. DSPy programs ko signatures aur modules ki tarah likhta, phir aapke metric par prompts compile karta hai.
  5. Data wale dohraaye kaamon ke liye faayde ka; kharaab metric ke saath bekaar.
