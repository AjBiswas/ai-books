1

A letter and its replyEk chitthi aur uska jawab

An API call is like posting a letter with a very precise form. You fill in which model, the instructions, the conversation, and how long the reply may be. The reply comes back with the text, the reason it stopped, and a receipt of tokens used.

API call ek bilkul sateek form wali chitthi bhejne jaisa hai. Aap bharte ho kaunsa model, instructions, baatcheet, aur jawab kitna lamba ho sakta hai. Jawab text, rukne ki wajah, aur use hue tokens ki raseed ke saath aata hai.

In the real world

The leaked-key story happens every weekLeak hui key ki kahani har hafte hoti hai

Someone pastes an API key into code and pushes it to a public GitHub repo. Bots scan GitHub constantly; within minutes the key is used to run thousands of requests, and the owner wakes up to a huge bill. Keep keys in environment variables or a secrets manager, add .env to .gitignore, set a spending limit in the provider console, and rotate any key that was ever exposed.

Koi API key code mein paste karke public GitHub repo par push kar deta hai. Bots lagaataar GitHub scan karte hain; minutes mein key se hazaaron requests chal jaati hain, aur maalik bade bill ke saath jaagta hai. Keys environment variables ya secrets manager mein rakho, .env ko .gitignore mein daalo, provider console mein spending limit lagao, aur jo bhi key kabhi bahar aayi use badal do.

2

When the post office is busyJab daakghar vyast ho

APIs fail sometimes: you're sending too fast (429, rate limited), the provider is overloaded (5xx / overloaded), or the network blips. The polite fix is retry with exponential backoff: wait a little, try again, wait twice as long, try again. But some errors must not be retried: a 400 means your request is wrong, and retrying just wastes time.

APIs kabhi fail hoti hain: aap bahut tez bhej rahe ho (429, rate limited), provider overloaded hai (5xx / overloaded), ya network atak gaya. Vinamra ilaaj hai exponential backoff ke saath retry: thoda ruko, phir try, do guna ruko, phir try. Par kuch errors ko retry nahi karna: 400 matlab aapki request galat hai, retry bas samay barbaad karta hai.

Engineer's note

Stream anything a human waits forJiska insaan intezaar kare use stream karo

Without streaming, the user stares at a spinner until the whole answer is written. With streaming, tokens appear as they're generated, so the first words show up in under a second. Same cost, much better feel. For long outputs, streaming also avoids HTTP timeouts. Always set max_tokens so a runaway answer can't run up your bill.

Streaming ke bina user tab tak spinner dekhta hai jab tak poora jawab na likh jaaye. Streaming ke saath tokens bante hi dikhte hain, toh pehle words second se kam mein aa jaate hain. Same kharch, kahin behtar ehsaas. Lambe outputs mein streaming HTTP timeouts se bhi bachaata hai. Hamesha max_tokens set karo taaki bhaagta jawab bill na badha de.

AI behaviour

Check why the model stoppedCheck karo model kyun ruka

Every response has a stop reason. end_turn/stop: finished normally. max_tokens/length: cut off mid-sentence, so don't show half an answer as if it were complete. tool_use: the model wants to call a tool (Chapter 16). refusal: the model declined. Code that ignores the stop reason ships truncated JSON and silent failures.

Har response mein rukne ki wajah hoti hai. end_turn/stop: aam tarah khatam. max_tokens/length: sentence ke beech kata, toh aadha jawab poora jaisa mat dikhao. tool_use: model tool call karna chahta hai (Chapter 16). refusal: model ne mana kiya. Rukne ki wajah ignore karne wala code adhoora JSON aur chupchaap failures ship karta hai.

For coders: the same call in three waysCoders ke liye: ek hi call teen tarah sepython
Anthropic Python SDK · pip install anthropicpython
import anthropic
client = anthropic.Anthropic()               # reads ANTHROPIC_API_KEY from the environment
resp = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    system="You are Acme's support assistant. Be brief.",
    messages=[{"role": "user", "content": "Where is order ORD-100232?"}],
)
print(resp.content[0].text, resp.stop_reason, resp.usage.input_tokens, resp.usage.output_tokens)
OpenAI-compatible SDK pointed at your laptop · pip install openaipython
from openai import OpenAI
client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")   # Ollama ignores the key
resp = client.chat.completions.create(
    model="qwen3:4b",
    max_tokens=512,
    messages=[{"role": "system", "content": "You are Acme's support assistant. Be brief."},
              {"role": "user", "content": "Where is order ORD-100232?"}],
)
print(resp.choices[0].message.content, resp.choices[0].finish_reason, resp.usage)
Streaming with the Anthropic SDKpython
with client.messages.stream(model="claude-opus-5-5", max_tokens=1024,
                            messages=[{"role": "user", "content": "Explain RAG in 3 lines."}]) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)

The official SDKs already retry 429 and 5xx errors with backoff (2 retries by default; configurable with max_retries). Don't wrap them in a second retry loop unless you need different behaviour. Note: on current Claude models, sampling knobs like temperature are rejected; depth is controlled with an effort setting instead.

Official SDKs pehle se 429 aur 5xx errors ko backoff ke saath retry karte hain (default 2 retries; max_retries se badal sakte ho). Jab tak alag behaviour na chahiye, unhe doosre retry loop mein mat lapeto. Dhyaan do: current Claude models par temperature jaise sampling knobs reject hote hain; gehraai effort setting se control hoti hai.

What we learnedHumne kya seekha

  1. A request names the model, the instructions, the messages and a token limit; the response gives text, a stop reason and usage.
  2. Keys live in environment variables, never in code; set a spending limit.
  3. Retry 429 and 5xx with backoff; fix 400s instead of retrying them.
  4. Stream for humans, and know what each call costs.
  1. Request mein model, instructions, messages aur token limit; response mein text, rukne ki wajah aur usage.
  2. Keys environment variables mein, code mein kabhi nahi; spending limit lagao.
  3. 429 aur 5xx ko backoff ke saath retry; 400 ko retry nahi, theek karo.
  4. Insaanon ke liye stream karo, aur har call ka kharch jaano.
