Every model in this book is the same kind of machine: it reads a window of tokens and writes the next token, one at a time. That design runs into two walls. Feed it a very long input and its attention gets blurry (context rot). Ask it for a long answer and it must take one step per token, however simple the text. Researchers attack both walls. This chapter explains the two newest attacks in plain words, RLM (Recursive Language Models) and NCM (Next-Concept Modeling), puts the other challengers on one page, and gives you a checklist for reading the next "this ends LLMs" headline calmly.

Is book ka har model ek hi tarah ki machine hai: tokens ki ek window padhta hai aur agla token likhta hai, ek-ek karke. Is design ke saamne do deewarein hain. Bahut lamba input do toh uska dhyaan dhundhla ho jaata hai (context rot). Lamba jawab maango toh har token ke liye ek step lena padta hai, text kitna bhi aasaan ho. Researchers dono deewaron par hamla karte hain. Yeh chapter do sabse naye hamle aasaan shabdon mein samjhaata hai, RLM (Recursive Language Models) aur NCM (Next-Concept Modeling), baaki challengers ko ek page par rakhta hai, aur agli "LLMs khatam" headline ko shaanti se padhne ki checklist deta hai.

2

RLM: Recursive Language ModelsRLM: Recursive Language Models

In December 2025, Alex Zhang, Tim Kraska and Omar Khattab at MIT published Recursive Language Models. The idea is simple: don't put the long input in the prompt at all. Store it as a variable inside a Python sandbox (a REPL). The model gets only the question and a note saying "the text is in a variable called context". It then does what a programmer would do: peeks at the text with code, splits it, and calls a fresh copy of a language model on each piece. Each copy reads only a small piece, so its attention stays sharp. The answers come back as short notes, and the root model combines them. If a piece is still too big, the copy can do the same trick again. That's the "recursive" part.

December 2025 mein MIT ke Alex Zhang, Tim Kraska aur Omar Khattab ne Recursive Language Models chhaapa. Idea seedha hai: lamba input prompt mein daalo hi mat. Use ek Python sandbox (REPL) ke andar variable mein rakho. Model ko sirf sawaal milta hai aur ek note ki "text context naam ke variable mein hai". Phir woh wahi karta hai jo programmer karta: code se text mein jhaankta hai, use todta hai, aur har tukde par language model ki ek nayi copy bulaata hai. Har copy sirf chhota tukda padhti hai, isliye uska dhyaan tez rehta hai. Jawab chhote notes ban kar lautte hain, aur root model unhe jodta hai. Agar tukda ab bhi bada ho, toh copy wahi chaal dobara chal sakti hai. Yahi "recursive" hissa hai.

The authors report that RLMs handled inputs about a hundred times longer than the model's own context window, and beat both the plain model and common long-context tricks (summarising old text, or retrieval agents) on four long-context tasks, at a similar or lower cost per question. They also fine-tuned a small model, RLM-Qwen3-8B, to work this way.

Authors ke mutaabik RLMs ne model ki apni context window se lagbhag sau guna lambe inputs sambhaale, aur chaar long-context tasks par saade model aur aam long-context tareekon (purane text ka saar banana, ya retrieval agents) dono ko haraaya, har sawaal par milte-julte ya kam kharch mein. Unhone ek chhote model, RLM-Qwen3-8B, ko bhi isi tarah kaam karne ke liye fine-tune kiya.

Engineer's note

An RLM is a harness patternRLM ek harness pattern hai

Look closely and you'll recognise every part: a code tool (Ch 16), a sandbox (Ch 27), sub-agents with clean contexts (Ch 19, and Book 2 Ch 9), and context kept outside the window until needed (Ch 10). It's not a new kind of neural network; it's a smarter way to run any existing model. The costs are real too: many model calls, more latency, and a code sandbox you must lock down.

Dhyaan se dekho toh har hissa pehchaana lagega: code tool (Ch 16), sandbox (Ch 27), saaf context wale sub-agents (Ch 19, aur Book 2 Ch 9), aur context ko zaroorat tak window ke bahar rakhna (Ch 10). Yeh naye tarah ka neural network nahi; kisi bhi maujooda model ko chalaane ka smart tareeka hai. Kharch bhi asli hain: kai model calls, zyaada latency, aur ek code sandbox jise aapko band karke rakhna hoga.

AI behaviour

"RLM" has two meanings"RLM" ke do matlab hain

Many blogs use RLM for Reasoning Language Model: a model that thinks before answering (Ch 9). The MIT paper uses it for Recursive Language Model. When you see the acronym, check which one is meant.

Kai blogs RLM ko Reasoning Language Model ke liye use karte hain: aisa model jo jawab se pehle sochta hai (Ch 9). MIT paper ise Recursive Language Model ke liye use karta hai. Acronym dikhe toh check karo kaunsa matlab hai.

3

NCM: Next-Concept ModelingNCM: Next-Concept Modeling

On 12 October 2026, Stanford's Hazy Research lab (Hermann Kumbong, Ishan Khare, Simran Arora, Azalia Mirhoseini, Christopher Ré and colleagues) released Next-Concept Modeling. It attacks the second wall. An LLM writes left to right. NCM writes the way an artist paints: first a rough sketch of the whole text, then more detail, then the fine strokes. It has two parts. A special tokenizer turns text into a hierarchy of codes: a few codes at the top that capture the broad shape, and more codes at each level below that add detail. A generator then creates the hierarchy one level at a time, with every code inside a level predicted at once. A decoder turns the finished hierarchy back into words.

12 October 2026 ko Stanford ki Hazy Research lab (Hermann Kumbong, Ishan Khare, Simran Arora, Azalia Mirhoseini, Christopher Ré aur saathi) ne Next-Concept Modeling jaari kiya. Yeh doosri deewar par hamla hai. LLM baayein se daayein likhta hai. NCM waise likhta hai jaise artist painting banata hai: pehle poore text ka kachcha sketch, phir zyaada detail, phir baareek strokes. Iske do hisse hain. Ek khaas tokenizer text ko codes ki hierarchy mein badalta hai: upar kuch codes jo mota aakaar pakadte hain, aur neeche har level par zyaada codes jo detail jodte hain. Phir ek generator hierarchy ko ek level ek baar mein banata hai, level ke andar har code ek saath. Ek decoder poori hierarchy ko wapas shabdon mein badalta hai.

The reported numbers are striking, but read what they compare against. NCM generated text 10 to 31 times faster than strong diffusion language models (21× on LM1B, 10× on OpenWebText, 31× on XSum summaries at matching quality), trained on roughly 4 to 5 times fewer tokens, and solved more hard Sudoku boards than the baselines. The models were small (about 100 million parameters, with preliminary tests up to 725 million), each checkpoint targets one task, and there was no head-to-head test against frontier LLMs. Code and checkpoints are public on GitHub (HazyResearch/ncm).

Bataaye gaye numbers chaunkaane wale hain, par dekho tulna kisse hai. NCM ne majboot diffusion language models se 10 se 31 guna tez text banaaya (LM1B par 21×, OpenWebText par 10×, XSum summaries par barabar quality ke saath 31×), lagbhag 4 se 5 guna kam tokens par train hua, aur baselines se zyaada mushkil Sudoku hal kiye. Models chhote the (lagbhag 10 crore parameters, 72.5 crore tak shuruaati tests), har checkpoint ek hi kaam ke liye hai, aur frontier LLMs se seedhi takkar nahi hui. Code aur checkpoints GitHub par khule hain (HazyResearch/ncm).

AI behaviour

"The end of LLMs"? Not yet"LLMs ka ant"? Abhi nahi

Social media called NCM "the end of LLMs" within days. The paper itself makes a narrower claim: a faster point on the non-autoregressive frontier. The "concepts" are learned codes, not ideas a human would name. And the authors list open questions: how it scales, training the tokenizer and generator together, and stopping early instead of always running every level. Treat it as an exciting direction, and watch for independent results at large scale.

Kuch hi dinon mein social media ne NCM ko "LLMs ka ant" keh diya. Paper khud chhota daava karta hai: non-autoregressive frontier par ek tez point. "Concepts" seekhe hue codes hain, aise ideas nahi jinhe insaan naam de. Aur authors khule sawaal ginaate hain: yeh kaise scale hota hai, tokenizer aur generator ko saath train karna, aur har level chalaane ki jagah jaldi rukna. Ise romaanchak disha maano, aur bade scale par alag nateejon ka intezaar karo.

What we learnedHumne kya seekha

  1. Plain LLMs hit two walls: long inputs blur (context rot), and output comes one token at a time.
  2. RLM keeps the long input in a code sandbox; the model reads it with code and calls copies of itself on small pieces.
  3. NCM writes text coarse to fine, a whole level at a time; fast against diffusion models, but still small and early.
  4. Diffusion, state-space and concept models are the other challengers.
  5. Ask: compared with what, at what scale, replicated, can I run it, what does it cost?
  1. Saade LLMs do deewaron se takraate hain: lambe inputs dhundhle (context rot), aur output ek-ek token.

  4. Diffusion, state-space aur concept models baaki challengers hain.
