Chapter 2 told you an LLM "guesses the next token". This chapter shows the machinery that does the guessing. A transformer is the same block repeated many times (32 times in a typical 7–8B model). Each block does two jobs: attention, where every token looks back at earlier tokens and gathers what it needs, and an MLP, where each token thinks on its own about what it gathered. Learn one block and you've learned the whole tower.

Chapter 2 ne bataaya ki LLM "agla token guess karta hai". Yeh chapter woh machinery dikhaata hai jo guess karti hai. Transformer ek hi block hai jo kai baar dohraaya jaata hai (aam 7–8B model mein 32 baar). Har block do kaam karta hai: attention, jahan har token pichhle tokens ko dekh kar zaroori cheez ikattha karta hai, aur MLP, jahan har token akele soch-vichaar karta hai ki kya mila. Ek block samjho, poora minar samajh gaye.

1

From tokens to vectorsTokens se vectors tak

A token is just an ID number, like 4,217. The first thing the model does is look up that ID in an embedding table: a big grid with one row of numbers per token in the vocabulary (4,096 numbers per row in many 7B models). Similar words end up with similar rows, the same idea as embeddings in Chapter 13. But "dog bites man" and "man bites dog" contain the same tokens, so the model also adds a position signal to each row, so it knows what came first.

Token sirf ek ID number hai, jaise 4,217. Model sabse pehle us ID ko embedding table mein dhoondhta hai: ek bada grid jisme vocabulary ke har token ke liye numbers ki ek row hai (kai 7B models mein har row mein 4,096 numbers). Milte-julte shabdon ki rows milti-julti ho jaati hain, wahi idea jo Chapter 13 ke embeddings mein tha. Par "kutta aadmi ko kaatta hai" aur "aadmi kutte ko kaatta hai" mein tokens wahi hain, isliye model har row mein position ka signal bhi jodta hai, taaki pata rahe pehle kya aaya.

2

Attention: every token asks a questionAttention: har token ek sawaal poochhta hai

Think of a classroom. Each student (token) writes three cards. A query: "what am I looking for?" A key: "what do I know about?" A value: "what I'll share if you pick me." Each student compares their query with everyone's keys; good matches get high scores. The scores become percentages (softmax), and the student takes that mix of everyone's values. In "the cat sat because it was tired", the token "it" sends out a query that matches the key of "cat" strongly, so "it" picks up cat-information. One rule makes this a language model: no peeking at the future. A token may only look at itself and earlier tokens; this is the causal mask.

Ek classroom socho. Har student (token) teen card likhta hai. Query: "main kya dhoondh raha hoon?" Key: "mujhe kis baare mein pata hai?" Value: "chuna gaya toh main kya bataunga." Har student apni query sabki keys se milaata hai; achhe mel ko ooncha score. Scores percentages ban jaate hain (softmax), aur student sabki values ka wahi mishran le leta hai. "billi baith gayi kyunki woh thaki thi" mein "woh" token ki query "billi" ki key se zor se milti hai, toh "woh" billi ki jaankari utha leta hai. Ek niyam ise language model banata hai: bhavishya mein jhaankna mana. Token sirf khud ko aur pichhle tokens ko dekh sakta hai; yahi causal mask hai.

3

The whole blockPoora block

Attention runs several times in parallel, as heads, each free to learn a different kind of looking: one may track grammar, another may track which name a pronoun refers to. Their results are joined and mixed. Then comes the MLP: each token, alone, goes through a wider layer (usually 4× wider) and back. Researchers think much of a model's stored knowledge lives in these MLPs. Two small tricks make deep towers trainable. Residual connections add each step's output to its input instead of replacing it, like writing notes in the margin rather than rewriting the page. Layer norm keeps the numbers in a healthy range before each step.

Attention kai baar parallel mein chalta hai, heads ki tarah, har ek alag tarah ka dekhna seekhne ke liye aazaad: ek grammar pakad sakta hai, doosra yeh ki sarvanaam kis naam ki baat kar raha hai. Unke nateeje jod kar milaaye jaate hain. Phir aata hai MLP: har token akele ek chaudi layer (aksar 4× chaudi) se guzar kar wapas aata hai. Researchers maante hain model ka bahut saara jama gyaan in MLPs mein rehta hai. Do chhoti chaalein gehre minar ko train karne laayak banaati hain. Residual connections har step ka output uske input mein jodte hain, badalte nahi, jaise page dobara likhne ki jagah haashiye mein notes likhna. Layer norm har step se pehle numbers ko sehatmand range mein rakhta hai.

q, k, v = h @ Wq, h @ Wk, h @ Wv                          # queries, keys, values
scores = q @ k.T / np.sqrt(dh)                            # how well each query matches each key
scores[np.triu(np.ones((T, T), bool), 1)] = -np.inf       # causal mask: no peeking at the future
att = softmax(scores)                                     # each row sums to 1
x = x + (att @ v) @ Wo                                    # residual: add, don't replace
x = x + relu(layer_norm(x) @ W1) @ W2                     # MLP, then residual again

4

Counting the weights, and the KV cacheWeights ginna, aur KV cache

In one block, attention has four d×d matrices (query, key, value, output) and the MLP has two d×4d matrices: about 12 × d² weights. With d = 4,096 that's about 200 million per block; 32 blocks make about 6.4 billion, plus the embedding table: that's a "7B" model. Now notice something about generation: when token 501 arrives, the keys and values of tokens 1–500 haven't changed. So the engine saves them, the KV cache, and only computes the new token's row. That's why the first token of an answer is slow (the whole prompt is processed) and the rest stream quickly, and why long contexts eat GPU memory (Chapter 44 does the maths).

Ek block mein attention ke paas chaar d×d matrices (query, key, value, output) hain aur MLP ke paas do d×4d matrices: lagbhag 12 × d² weights. d = 4,096 ho toh har block mein lagbhag 20 crore; 32 blocks mein lagbhag 6.4 arab, plus embedding table: yahi "7B" model hai. Ab generation ke baare mein ek baat dekho: jab token 501 aata hai, tokens 1–500 ki keys aur values nahi badli. Toh engine unhe bacha leta hai, KV cache, aur sirf naye token ki row nikaalta hai. Isiliye jawab ka pehla token dheema hota hai (poora prompt process hota hai) aur baaki tez stream hote hain, aur isiliye lambe contexts GPU memory khaate hain (Chapter 44 hisaab lagaata hai).

AI behaviour

Why "lost in the middle" happens"Beech mein kho jaana" kyun hota hai

Attention is a fixed budget of 100% per token, spread over everything before it. With 100,000 tokens of context, a key fact in the middle competes with a huge crowd, and models in practice attend most to the start and the end. That's the mechanical root of context rot (Ch 10), and why RLM (Ch 35) keeps long inputs outside the window.

Attention har token ke liye 100% ka tay budget hai, pichhli har cheez par baanta hua. 1,00,000 tokens ke context mein beech ka zaroori fact badi bheed se muqaabla karta hai, aur models asal mein shuruaat aur aakhir par sabse zyaada dhyaan dete hain. Yahi context rot (Ch 10) ki mechanical jad hai, aur isiliye RLM (Ch 35) lambe inputs window ke bahar rakhta hai.
