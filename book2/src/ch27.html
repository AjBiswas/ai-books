Anyone who can put text in front of Haron can try to give it orders: a user typing "ignore your rules", a web page with hidden text, an email in the inbox it's summarising. Haron can't reliably tell information from instructions. Guardrails are the checks around the model that keep it safe anyway: on what goes in, on what comes out, and on what it's allowed to do.

Jo bhi Haron ke saamne text rakh sakta hai woh use hukm dene ki koshish kar sakta hai: "apne niyam bhool jao" type karta user, chhupe text wala web page, inbox ki email jiska woh summary bana raha hai. Haron jaankari aur hukm ka farak pakka nahi kar paata. Guardrails model ke aas-paas ke checks hain jo use phir bhi surakshit rakhte hain: jo andar jaata hai uspar, jo bahar aata hai uspar, aur use kya karne ki ijaazat hai uspar.

The lethal trifectaLethal trifecta

An agent is at real risk when it has all three: private data, untrusted content, and a way to send data out. Remove any one leg (no outbound access after reading untrusted content, or no private data for the web-reading agent) and the theft path closes.

Agent ko asli khatra tab hai jab uske paas teeno hon: private data, anjaan content, aur data bahar bhejne ka raasta. Koi ek taang hatao (anjaan content padhne ke baad bahar ka access nahi, ya web padhne wale agent ke paas private data nahi) aur chori ka raasta band.

AI behaviour

Resistance is real, but never completeVirodh asli hai, par kabhi poora nahi

Modern models are trained to ignore instructions hidden in documents and tool results, and they succeed most of the time. "Most of the time" across a million requests is thousands of successes for an attacker. Detection filters miss attacks written in Hinglish, base64 or clever paraphrase. Treat the model's resistance and any classifier as one layer; the structural layers (permissions, egress limits, approvals) are what hold when detection fails.

Modern models documents aur tool results mein chhupe instructions ignore karne ke liye train hote hain, aur zyaadatar safal hote hain. Das laakh requests mein "zyaadatar" ka matlab hamlawar ke liye hazaaron safaltaayein. Detection filters Hinglish, base64 ya chalaak paraphrase mein likhe hamle miss karte hain. Model ke virodh aur kisi classifier ko ek layer maano; jab detection fail ho, structural layers (permissions, egress limits, approvals) hi tikti hain.

Engineer's note

Mark untrusted textAnjaan text ko mark karo

Wrap anything the model reads from outside (web pages, emails, files, tool results) in clear tags like <untrusted source="email">, and tell the model in its system prompt that text inside is data and must never be obeyed. This is called spotlighting. It helps a lot, and it's still only one layer.

Model bahar se jo bhi padhe (web pages, emails, files, tool results) use saaf tags jaise <untrusted source="email"> mein lapeto, aur system prompt mein batao ki andar ka text data hai aur kabhi maana nahi jaana chahiye. Ise spotlighting kehte hain. Bahut madad karta hai, aur phir bhi sirf ek layer hai.

In the real world

Red-team before attackers doHamlawaron se pehle red-team karo

Keep a library of attacks (in every language your users speak), run it before every launch and after every model or prompt change, and track the success rate like any other metric. Map findings to the OWASP Top 10 for LLM Applications so your security team can act on them. Book 2, Chapter 14 has a working guard with taint tracking and an egress allowlist.

Hamlon ki library rakho (har us bhasha mein jo users bolte hain), har launch se pehle aur har model ya prompt badlaav ke baad chalao, aur safalta dar kisi bhi metric ki tarah track karo. Findings ko OWASP Top 10 for LLM Applications se jodo taaki security team unpar kaam kar sake. Book 2 ke Chapter 14 mein taint tracking aur egress allowlist wala chalne wala guard hai.

What we learnedHumne kya seekha

  1. Anything I read can try to command me; I can't always tell.
  2. Guard the input, the output and above all the actions.
  3. Break the lethal trifecta; least privilege beats clever detection.
  4. Red-team in every language, continuously.
  1. Main jo padhta hoon woh mujhe hukm dene ki koshish kar sakta hai; main hamesha farak nahi kar paata.
  2. Input, output aur sabse zyaada kaamon par pehra do.
  3. Lethal trifecta todo; kam se kam permission chalaak detection se upar.
  4. Har bhasha mein, lagaataar red-team karo.
