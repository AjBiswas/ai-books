Imagine a brilliant new colleague on their first day. They know a lot about everything, but nothing about your company, your customers or what you meant. If you say "write something about our product", you'll get something generic. If you brief them properly, you'll get exactly what you need. Haron is that colleague, and a prompt is your briefing.

Socho pehle din ka ek hoshiyaar naya saathi. Use har cheez ke baare mein bahut pata hai, par aapki company, customers ya aapke matlab ke baare mein kuch nahi. Agar aap kaho "product ke baare mein kuch likho", toh kuch aam sa milega. Agar theek se samjhao, toh bilkul wahi milega jo chahiye. Haron woh saathi hai, aur prompt aapki briefing.

The golden testSunehra test

Show your prompt to a colleague who knows nothing about the task. If they'd have to ask you questions before starting, Haron would too, except Haron won't ask; it will guess. Every question they'd ask is something missing from your prompt.

Apna prompt kisi aise saathi ko dikhao jise kaam ke baare mein kuch nahi pata. Agar unhe shuru karne se pehle aapse sawaal poochne padein, toh Haron ko bhi padte, bas Haron poochega nahi; andaaza lagayega. Har woh sawaal jo woh poochte, aapke prompt se gaayab cheez hai.

"Don't" is weaker than "do""Mat karo" se "karo" zyaada majboot

Telling a model only what not to do leaves it guessing what you do want, and naming the forbidden thing can even put it in its mind. Describe the target instead, and explain why: the reason helps Haron generalise to cases you didn't list.

Model ko sirf kya nahi karna batane se use andaaza lagana padta hai ki aap kya chahte ho, aur mana ki gayi cheez ka naam lene se woh uske dimaag mein aa bhi sakti hai. Iske badle nishaana batao, aur wajah bhi: wajah Haron ko un cases mein bhi madad karti hai jo aapne list nahi kiye.

Engineer's note

Wrap data in tagsData ko tags mein lapeto

When a prompt contains documents, emails or user text, put each inside clear tags such as <email>…</email> or <document id="2">. The model can then tell your instructions from the material, you can refer to parts by name ("quote from document 2"), and it's harder for text inside the data to pretend to be an instruction (Chapter 27).

Jab prompt mein documents, emails ya user ka text ho, har ek ko saaf tags mein rakho jaise <email>…</email> ya <document id="2">. Tab model aapke instructions ko saamagri se alag pehchaan sakta hai, aap hisson ko naam se bula sakte ho ("document 2 se quote karo"), aur data ke andar ke text ke liye instruction hone ka naatak karna mushkil hota hai (Chapter 27).

AI behaviour

Newer models follow instructions literallyNaye models instructions ko shabdshah maante hain

Older models needed SHOUTING ("YOU MUST ALWAYS…") to pay attention. Current models follow instructions closely, so shouting makes them over-apply a rule everywhere. Write calmly and precisely, like a good brief to a professional. If you want extra effort ("go beyond the basics"), say so; models no longer assume it.

Purane models ko dhyaan dene ke liye CHILLAANA padta tha ("YOU MUST ALWAYS…"). Aaj ke models instructions ko kareeb se maante hain, isliye chillaane se woh niyam ko har jagah zaroorat se zyaada laagu karte hain. Shaanti aur sateekta se likho, jaise kisi professional ko achhi briefing. Agar extra mehnat chahiye ("basics se aage jao"), toh kaho; models ab khud nahi maante.

In the real world

Prompts are codePrompts bhi code hain

In a product, a prompt is a piece of software: keep it in version control, review changes, give it an owner, and test every change against an eval set before shipping (Chapters 26 and 28). A one-word change can shift results for thousands of users.

Product mein prompt software ka tukda hai: use version control mein rakho, badlaav review karo, uska owner banao, aur ship karne se pehle har badlaav ko eval set par test karo (Chapter 26 aur 28). Ek word ka badlaav hazaaron users ke nateeje badal sakta hai.

For coders: a reusable prompt templateCoders ke liye: dobara use hone wala prompt templatepython 
SYSTEM = """You are the support assistant for Acme, an online electronics shop in India.
Customers write in English, Hindi or Hinglish; reply in the language they used.

Your goal: resolve the customer's issue in as few messages as possible.
- Use only facts from <policy> and <order>. If something isn't there, say you'll
  connect them to a human, because a wrong promise costs us more than a handover.
- Keep replies under 80 words: customers read on phones.
- End with one clear next step."""

def build_user_turn(policy: str, order: dict, message: str) -> str:
    return (f"<policy>\n{policy}\n</policy>\n"
            f"<order>\n{json.dumps(order, ensure_ascii=False)}\n</order>\n"
            f"<customer_message>\n{message}\n</customer_message>")

Stable instructions go in the system prompt; per-request data goes in the user turn, wrapped in tags. This also keeps the system prompt identical across requests, which makes prompt caching work (Chapter 29).

Sthir instructions system prompt mein; har request ka data user turn mein, tags mein lipta hua. Isse system prompt har request mein same rehta hai, jisse prompt caching kaam karti hai (Chapter 29).

What we learnedHumne kya seekha

  1. Brief me like a smart new colleague: who, what, why, for whom, how long.
  2. A strong prompt has role and context, task, data in tags, rules with reasons, examples, and an output format.
  3. Tell me what to do and why, not just what to avoid.
  4. Treat prompts like code: versioned, reviewed, tested.
  1. Mujhe hoshiyaar naye saathi ki tarah samjhao: kaun, kya, kyun, kiske liye, kitna lamba.
  2. Majboot prompt mein role aur context, kaam, tags mein data, wajah ke saath niyam, examples, aur output format.
  3. Mujhe batao kya karna hai aur kyun, sirf kya nahi karna nahi.
  4. Prompts ko code ki tarah rakho: versioned, reviewed, tested.
