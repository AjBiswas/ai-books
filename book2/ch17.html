Building AgentsAgents Banana

"Agent" is the most used and least defined word in AI. Here's a useful definition: an agent is a model that decides its own next step in a loop, using tools, until a goal is met. That's powerful for open-ended work and wasteful for predictable work. This chapter shows the whole range from fixed workflows to autonomous agents, the frameworks people use, and the honest question to ask first: do you need an agent at all?

"Agent" AI ka sabse zyaada use hone wala aur sabse kam paribhaashit shabd hai. Kaam ki paribhasha: agent aisa model hai jo loop mein, tools use karke, lakshya poora hone tak apna agla step khud tay karta hai. Khule kaam ke liye taakatwar, pehle se pata kaam ke liye barbaadi. Yeh chapter fixed workflows se autonomous agents tak poori range, log jo frameworks use karte hain, aur pehle poochne wala imaandaar sawaal dikhata hai: kya aapko agent chahiye bhi?

The autonomy ladderAutonomy ki seedhi

RememberYaad rakho

Climb only as high as you must. A fixed workflow is cheaper, faster, easier to test and easier to explain to an auditor. Use an agent when the steps genuinely can't be known in advance, the outcome is worth the extra cost, and mistakes can be caught (tests, review, undo).

Utna hi upar chadho jitna zaroori ho. Fixed workflow sasta, tez, test karne mein aasaan aur auditor ko samjhaane mein aasaan hai. Agent tab use karo jab steps sach mein pehle se pata na ho sakein, nateeja extra kharch ke laayak ho, aur galtiyaan pakdi ja sakein (tests, review, undo).

3

The agent loopAgent loop

At the top of the ladder, the loop is simple: the model looks at the goal and everything so far, picks a tool (or decides it's done), your code runs the tool, the result goes into the context, repeat. The hard parts are around the loop: when to stop, what to do when a tool fails, how to keep the context clean, and how to stop it doing something harmful.

Seedhi ke top par loop seedha hai: model lakshya aur ab tak ka sab dekhta hai, ek tool chunta hai (ya tay karta hai kaam ho gaya), aapka code tool chalaata hai, result context mein jaata hai, dohraao. Mushkil hisse loop ke aas-paas hain: kab rukna, tool fail ho toh kya karna, context saaf kaise rakhna, aur use nuksaan karne se kaise rokna.

Engineer's note

Learn the loop before the frameworkFramework se pehle loop seekho

Frameworks change every few months; the loop doesn't. Build one agent with plain code first (Chapter 16's lab is 60 lines). Then you'll know what a framework is doing for you, and you'll be able to debug it when it does something surprising. Many production teams end up with a thin custom loop anyway.

Frameworks har kuch mahine badalte hain; loop nahi. Pehle seedhe code se ek agent banao (Chapter 16 ka lab 60 lines ka hai). Tab aapko pata hoga framework aapke liye kya kar raha hai, aur kuch ajeeb kare toh debug kar paoge. Kai production teams aakhir mein patla custom loop hi rakhti hain.

AI behaviour

Agents declare victory early, or never stopAgents jaldi jeet maan lete hain, ya kabhi nahi rukte

Two classic failures: saying "done!" when the task isn't finished (or a tool silently failed), and wandering for 50 steps re-reading the same files. Give a clear definition of done that code can check, cap steps and tokens, detect repeated identical calls, and make the agent show evidence (test output, a link, a record ID) before it may finish.

Do purani galtiyaan: kaam adhoora ho (ya tool chupchaap fail hua ho) tab bhi "ho gaya!" bolna, aur 50 steps tak same files dobara padhte bhatakna. Code se check hone laayak "done" ki saaf paribhasha do, steps aur tokens par limit, dohraayi same calls pakdo, aur khatam karne se pehle agent se saboot maango (test output, link, record ID).

In the real world

Hosted agentsHosted agents

Providers now also run the whole agent for you: the loop, a sandboxed computer for tools, files and long sessions (for example Anthropic's Managed Agents). You trade some control for not running infrastructure. Whether you self-host or use a hosted agent, the design questions in this chapter (autonomy, tools, stop rules, approvals) stay the same.

Providers ab poora agent bhi aapke liye chalaate hain: loop, tools ke liye sandboxed computer, files aur lambe sessions (jaise Anthropic ke Managed Agents). Infrastructure na chalaane ke badle thoda control chhodte ho. Khud host karo ya hosted agent lo, is chapter ke design sawaal (autonomy, tools, rukne ke niyam, approvals) wahi rehte hain.

✓

What we learnedHumne kya seekha

  1. An agent decides its own next step in a loop with tools.
  2. Climb the autonomy ladder only as far as the task needs.
  3. Chaining, routing, parallel, orchestrator-workers and evaluator-optimiser solve most problems.
  4. Stop rules, evidence and approvals make agents safe; learn the plain loop before any framework.
  1. Agent tools ke saath loop mein apna agla step khud tay karta hai.
  2. Autonomy ki seedhi par utna hi chadho jitna kaam ko chahiye.
  3. Chaining, routing, parallel, orchestrator-workers aur evaluator-optimiser zyaadatar samasyaayein suljhaate hain.
  4. Rukne ke niyam, saboot aur approvals agents ko surakshit banaate hain; kisi framework se pehle seedha loop seekho.
