Shipping to ProductionProduction mein Bhejna

Your AI app works on your laptop. Now it must work for 10,000 people at once, at 2 a.m., when the model provider is having a bad day and someone is trying to abuse it. Shipping to production is mostly normal software engineering (servers, queues, retries, monitoring) plus a few AI-specific twists: slow, expensive, sometimes-wrong calls in the middle of every request.

Aapki AI app laptop par chalti hai. Ab use ek saath 10,000 logon ke liye chalna hai, raat 2 baje, jab model provider ka bura din ho aur koi use galat use karne ki koshish kar raha ho. Production mein bhejna zyaadatar aam software engineering hai (servers, queues, retries, monitoring) aur kuch AI-wale mod: har request ke beech mein dheemi, mehengi, kabhi-galat calls.

Don't make users wait for slow workUsers ko dheeme kaam ka intezaar mat karwao

A chat reply should stream immediately. But "analyse these 40 contracts" can take ten minutes, and an HTTP request held open that long will time out and break. Put long work on a queue: reply at once with a job ID, let workers process it in the background, and notify the user when it's done.

Chat ka jawab turant stream hona chahiye. Par "in 40 contracts ka vishleshan karo" das minute le sakta hai, aur itni der khuli HTTP request time out hokar toot jaayegi. Lamba kaam queue par daalo: turant job ID ke saath jawab do, workers ko background mein process karne do, aur khatam hone par user ko batao.

AI behaviour

The provider will have bad daysProvider ke bure din aayenge

Model APIs return overloaded errors at peak times, slow down, and occasionally go down. Models also get updated or retired on a schedule. Plan for it: timeouts on every call, retries with backoff, a fallback model (ideally from another provider) that has passed the same evals, and a graceful message when everything fails.

Model APIs peak samay par overloaded errors lautaati hain, dheemi hoti hain, aur kabhi band bhi. Models tay schedule par update ya retire bhi hote hain. Iska plan karo: har call par timeout, backoff ke saath retries, fallback model (behtar hai doosre provider ka) jo same evals pass kar chuka ho, aur sab fail ho toh shaalin sandesh.

Engineer's note

Put a gateway between your app and modelsApp aur models ke beech gateway rakho

A thin AI gateway (your own module, or a product like LiteLLM) gives one place for API keys, retries, fallbacks, routing, budgets, caching and logging. Your app code calls the gateway, never a provider directly, so switching models is a config change. Book 2, Part III builds a full enterprise gateway.

Patla AI gateway (aapka apna module, ya LiteLLM jaisa product) API keys, retries, fallbacks, routing, budgets, caching aur logging ke liye ek jagah deta hai. Aapka app code gateway ko call karta hai, provider ko seedhe kabhi nahi, toh model badalna config ka badlaav hai. Book 2 ka Part III poora enterprise gateway banata hai.

In the real world

Where to run itKahan chalaayein

The app itself is ordinary: containers on a cloud platform, or serverless functions for small apps. Models come from APIs, a cloud AI platform (Bedrock, Vertex AI, Azure AI Foundry) when your company already uses that cloud, or self-hosted GPUs with vLLM when data can't leave (Book 2, Chapter 15). Choose the boring option for everything except what makes your product special.

App khud aam hai: cloud platform par containers, ya chhoti apps ke liye serverless functions. Models APIs se aate hain, cloud AI platform (Bedrock, Vertex AI, Azure AI Foundry) se jab company pehle se woh cloud use karti ho, ya vLLM ke saath self-hosted GPUs se jab data bahar na ja sake (Book 2, Chapter 15). Jo aapke product ko khaas banaata hai uske alawa har cheez ke liye boring option chuno.

What we learnedHumne kya seekha

  1. A production AI app = front-end, backend, gateway, models, knowledge store, queue, workers and observability.
  2. Stream quick replies; queue slow work.
  3. Timeouts, retries, fallbacks, idempotency and budgets on every model call.
  4. Launch only after evals, red-team, load tests and a rollback plan.
  1. Production AI app = front-end, backend, gateway, models, knowledge store, queue, workers aur observability.
  2. Jaldi jawab stream karo; dheema kaam queue mein.
  3. Har model call par timeouts, retries, fallbacks, idempotency aur budgets.
  4. Evals, red-team, load tests aur rollback plan ke baad hi launch.
