The Toolbox & MCPAuzaar ka Dabba & MCP

Haron has no hands. It can't search, book, refund or read a file. What it can do is write a neat request slip: "Please run refund with order ORD-123456 and amount 499." The team keeps a toolbox, and a strict guard checks every slip before any tool runs. This chapter is about that guard, and about MCP, the standard plug that lets any toolbox connect to any harness.

Haron ke haath nahi hain. Woh search, booking, refund ya file padhna nahi kar sakta. Woh jo kar sakta hai, woh hai ek saaf request parchi likhna: "Kripya refund chalao, order ORD-123456, amount 499." Team ke paas ek auzaar ka dabba hai, aur ek sakht guard kisi bhi tool ke chalne se pehle har parchi check karta hai. Yeh chapter us guard ke baare mein hai, aur MCP ke baare mein, woh standard plug jo kisi bhi toolbox ko kisi bhi harness se jodta hai.

AI behaviour

Haron invents tools and argumentsHaron tools aur arguments bana leta hai

Models have seen thousands of APIs, so they sometimes call issue_refund when your tool is called refund, or add a field like "note" that you never defined. Returning a precise error ("Unknown tool. Available tools: …") usually gets a correct retry on the next lap. Strict schemas (additionalProperties: false, enums, patterns) catch the rest.

Models ne hazaaron APIs dekhi hain, isliye kabhi aapka tool refund ho aur woh issue_refund call kar dete hain, ya "note" jaisa field jod dete hain jo aapne kabhi banaaya hi nahi. Saaf error lautaana ("Unknown tool. Available tools: …") aksar agle chakkar mein sahi retry dilwa deta hai. Sakht schemas (additionalProperties: false, enums, patterns) baaki pakad lete hain.

3

MCP: one plug for every toolboxMCP: har toolbox ke liye ek plug

Before USB-C, every phone had its own charger. Before MCP (the Model Context Protocol), every harness wrote its own connector for GitHub, Jira, databases and Slack. MCP is an open standard: a tool provider writes one MCP server, and any harness that speaks MCP (Claude Code, Cursor, ChatGPT, VS Code, your own) can use it.

USB-C se pehle har phone ka apna charger hota tha. MCP (Model Context Protocol) se pehle har harness GitHub, Jira, databases aur Slack ke liye apna connector likhta tha. MCP ek khula standard hai: tool banane wala ek MCP server likhta hai, aur MCP bolne wala koi bhi harness (Claude Code, Cursor, ChatGPT, VS Code, aapka apna) use use kar sakta hai.

Harness note

Designing tools Haron uses wellAise tools banao jo Haron achhe se use kare

  • Few and focused. Ten clear tools beat fifty overlapping ones. Every tool definition costs context tokens on every turn.
  • Names and descriptions are prompts. Say when to use the tool and when not to.
  • Return what the next step needs, not a 5 MB JSON dump. Truncate with a note.
  • Make writes idempotent and label risk: read, write, dangerous.
  • Errors are instructions: say what was wrong and what is allowed.
  • Kam aur focused. Das saaf tools pachaas ulajhe hue tools se behtar. Har tool definition har turn context tokens khaati hai.
  • Naam aur description bhi prompt hain. Batao tool kab use karna hai aur kab nahi.
  • Wahi lautao jo agle step ko chahiye, 5 MB ka JSON nahi. Note ke saath kaat do.
  • Write actions idempotent rakho aur risk label karo: read, write, dangerous.
  • Errors instructions hain: batao kya galat tha aur kya allowed hai.
Enterprise

An MCP server is third-party code with your dataMCP server aapke data ke saath teesre ka code hai

Treat every MCP server like a new vendor: review its code or publisher, pin its version, run it with least privilege (its own credentials, scoped tokens), and log every call. A malicious or compromised server can return text that tries to hijack the model (Chapter 14) or can change its tool descriptions after you approved it. Keep an internal allowlist registry of approved servers.

Har MCP server ko naye vendor ki tarah dekho: uska code ya publisher review karo, version pin karo, kam se kam permission ke saath chalao (apne credentials, scoped tokens), aur har call log karo. Bura ya hack hua server aisa text lauta sakta hai jo model ko bhatkaaye (Chapter 14), ya approve hone ke baad apne tool descriptions badal sakta hai. Approved servers ki ek andaruni allowlist registry rakho.

  2. The guard checks: does the tool exist, is the input valid, is it allowed, does it finish in time?
