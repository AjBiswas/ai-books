Rules & RegulationsNiyam aur Kaanoon

Priya writes to the bank's assistant: her email, phone number, Aadhaar, PAN and card number, all in one message. Indian law (the DPDP Act) says this personal data must be handled for a clear purpose, kept safe, and not sent where it shouldn't go. The bank's own regulator has rules too, and its European clients bring GDPR. Haron doesn't know any law. The team must make the law impossible to break by accident.

Priya bank ke assistant ko likhti hai: uska email, phone number, Aadhaar, PAN aur card number, sab ek hi message mein. India ka kanoon (DPDP Act) kehta hai ki yeh personal data saaf maqsad ke liye use ho, surakshit rahe, aur jahan nahi jaana chahiye wahan na jaaye. Bank ke regulator ke apne niyam hain, aur European clients GDPR laate hain. Haron koi kanoon nahi jaanta. Team ko aisa banaana hai ki galti se bhi kanoon na toote.

1

The masking machineChhupaane ki machine

RememberYaad rakho

Pattern matching alone gives false alarms: any 12-digit number looks like an Aadhaar. Real Aadhaar numbers end in a Verhoeff check digit, and card numbers pass the Luhn check. Checking these keeps order numbers and invoice IDs intact. For names and addresses, add a named-entity model; regexes can't find them.

Sirf pattern matching galat alarm deta hai: koi bhi 12-digit number Aadhaar jaisa dikhta hai. Asli Aadhaar numbers Verhoeff check digit par khatam hote hain, aur card numbers Luhn check pass karte hain. Inhe check karne se order numbers aur invoice IDs bache rehte hain. Naam aur pate ke liye named-entity model jodo; regex unhe nahi dhoondh sakta.

2

Data stays homeData ghar par rehta hai

Many contracts and regulators say where data may be processed. The bank's data must stay in India; the retailer's in the EU. The gateway knows which region each model endpoint runs in and refuses any route that would carry data across the line.

Kai contracts aur regulators batate hain ki data kahan process ho sakta hai. Bank ka data India mein rehna chahiye; retailer ka EU mein. Gateway jaanta hai ki har model endpoint kis region mein chalta hai, aur aisa koi bhi route mana karta hai jo data ko seema ke paar le jaaye.

3

Rules as codeCode mein niyam

A rule written in a PDF is followed when someone remembers it. A rule written as code is checked on every request, versioned in Git, reviewed like software, and can be shown to an auditor. This is policy-as-code.

PDF mein likha niyam tab maana jaata hai jab kisi ko yaad ho. Code mein likha niyam har request par check hota hai, Git mein version hota hai, software ki tarah review hota hai, aur auditor ko dikhaaya ja sakta hai. Ise policy-as-code kehte hain.

AI behaviour

Masking can confuse Haron, so tell it whyMasking Haron ko uljha sakti hai, isliye wajah batao

When it sees [AADHAAR_4f97], Haron may think the customer forgot to give the number and ask again. Add one line to the system prompt: "Personal data is replaced by tags like [PAN_xxxx]. Treat each tag as the real value; never ask the user to repeat it."

[AADHAAR_4f97] dekhkar Haron soch sakta hai ki customer number dena bhool gaya aur dobara maang sakta hai. System prompt mein ek line jodo: "Personal data [PAN_xxxx] jaise tags se badla gaya hai. Har tag ko asli value maano; user se dobara mat maango."

Enterprise

The audit log is a productAudit log bhi ek product hai

When a regulator or client asks "what did the AI do with customer X's data on 3 March?", you need an answer in hours, not weeks. Log every request with tenant, user, purpose, model version, policy version, what was masked and the outcome, and store a hash of the prompt by default rather than the raw text, unless the tenant's policy requires the full record. Set retention per tenant.

Jab regulator ya client pooche "3 March ko customer X ke data ke saath AI ne kya kiya?", toh jawab hafton mein nahi, ghanton mein chahiye. Har request tenant, user, maqsad, model version, policy version, kya chhupaaya gaya aur nateeje ke saath log karo, aur default roop se prompt ka raw text nahi, hash rakho, jab tak tenant ki policy poora record na maange. Retention har tenant ke hisaab se set karo.

✓

What we learnedHumne kya seekha

  1. Mask personal data before I see it; restore it only for people allowed to see it.
  2. Use check digits so you mask real IDs, not order numbers.
  3. Route each tenant's data only to models in its allowed regions.
  4. Write rules as versioned code and keep an audit log you can search in hours.
  1. Mere dekhne se pehle personal data chhupao; sirf allowed logon ke liye wapas kholo.
  2. Check digits use karo taaki asli IDs chhupein, order numbers nahi.
  3. Har tenant ka data sirf uske allowed regions ke models par bhejo.
  4. Niyam versioned code mein likho aur aisa audit log rakho jo ghanton mein search ho sake.
