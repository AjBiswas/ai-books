Hooks, Skills & PoliciesHooks, Skills & Policies

You can ask Haron never to force-push to the main branch. Most days it will listen. But "most days" is not good enough for a bank. A prompt is advice; a hook is a law. Hooks are small pieces of code that run at fixed moments in the loop and can watch, change or block what happens, whatever the model says.

Aap Haron se keh sakte ho ki main branch par kabhi force-push mat karna. Zyaadatar din woh maanega. Par bank ke liye "zyaadatar din" kaafi nahi. Prompt salaah hai; hook kanoon hai. Hooks chhote code ke tukde hain jo loop mein tay pal par chalte hain aur jo ho raha hai use dekh, badal ya rok sakte hain, model chahe jo bole.

How much freedom? Permission modesKitni aazaadi? Permission modes

Skills: know-how in a folderSkills: ek folder mein gyaan

A skill is a folder with a SKILL.md file: a short name and description at the top (always visible to Haron), and detailed steps, scripts and templates below (read only when needed). Teams package their way of doing things, like "how we write release notes" or "how to file a GST return", once, and every agent can use it.

Skill ek folder hai jisme SKILL.md file hoti hai: upar chhota naam aur description (Haron ko hamesha dikhta hai), aur neeche detailed steps, scripts aur templates (sirf zaroorat par padhe jaate hain). Teams apna kaam karne ka tareeka, jaise "hum release notes kaise likhte hain" ya "GST return kaise file karein", ek baar package karti hain, aur har agent use use kar sakta hai.

skills/gst-return/SKILL.mdmarkdown
---
name: gst-return
description: File a monthly GST return (GSTR-3B) from the sales ledger. Use when asked about GST filing.
---
1. Read the ledger with the `read_sheet` tool; total taxable value by rate (5, 12, 18, 28%).
2. Run scripts/reconcile.py to match against GSTR-2B input credit.
3. Fill templates/gstr3b.json. Never submit; ask a human to review and file.
AI behaviour

Haron can be talked out of a prompt ruleHaron ko baaton se prompt ka niyam tudwaya ja sakta hai

A long chat, an urgent-sounding user ("the CEO needs this now!") or text hidden in a document can all push Haron past an instruction in its prompt. Hooks run outside the model, so none of that reaches them. Put every rule that must hold in a hook; keep prompts for guidance and style.

Lambi chat, jaldi-wala user ("CEO ko abhi chahiye!") ya document mein chhupa text, sab Haron ko prompt ke niyam ke paar dhakel sakte hain. Hooks model ke bahar chalte hain, isliye inme se kuch unhe nahi chhoota. Jo niyam har haal mein maana jaana chahiye, use hook mein daalo; prompts ko salaah aur style ke liye rakho.

Enterprise

Central hooks, managed settingsCentral hooks, managed settings

In a company, hooks and permission rules should come from a central, version-controlled policy that individual users can't switch off (Claude Code, for example, supports organisation-managed settings). Typical company hooks: block secrets in prompts, block edits to production config, require a ticket ID for deploys, log every shell command to the SIEM.

Company mein hooks aur permission niyam ek central, version-controlled policy se aane chahiye jise koi user band na kar sake (jaise Claude Code organisation-managed settings support karta hai). Aam company hooks: prompts mein secrets rokna, production config ke edits rokna, deploy ke liye ticket ID zaroori karna, har shell command SIEM mein log karna.

For coders: the hook busCoders ke liye: hook buscode/harness/hooks.py 
hooks = HookBus()

@hooks.on("pre_tool")
def no_force_push(call, messages):
    if call.name == "run_shell" and "push --force" in call.input["cmd"]:
        return Deny("force-push to shared branches is not allowed")

@hooks.on("pre_tool")
def always_dry_run_deploys(call, messages):
    if call.name == "run_shell" and call.input["cmd"].startswith("deploy") \
            and "--dry-run" not in call.input["cmd"]:
        return Modify({"cmd": call.input["cmd"] + " --dry-run"})

Real hooks should parse commands properly (shlex), not just search strings: git push -f and git push --force-with-lease are also force-pushes.

Asli hooks ko commands theek se parse karne chahiye (shlex), sirf string search nahi: git push -f aur git push --force-with-lease bhi force-push hain.

What we learnedHumne kya seekha

  1. Prompts guide me; hooks bind me.
  2. Hooks run before and after my requests and tool calls, and at the stop.
  3. A hook can allow, deny, modify or just record.
  4. Give me only the freedom the task needs, and ask a human for dangerous steps.
  5. Skills let me load a team's know-how only when I need it.
  1. Prompts mujhe raah dikhaate hain; hooks mujhe baandhte hain.
  2. Hooks meri requests aur tool calls se pehle aur baad mein, aur rukne par chalte hain.
  3. Hook allow, mana, badal ya bas record kar sakta hai.
  4. Mujhe utni hi aazaadi do jitni kaam ko chahiye, aur khatarnaak steps ke liye insaan se poochho.
  5. Skills mujhe team ka gyaan tabhi load karne dete hain jab zaroorat ho.
