Packing the DiaryDiary Pack Karna

Packing for a trip is a skill: take what you need, put the things you always use where they're easy to reach, and leave the rest at home. Packing Haron's diary is the same skill, and it has a grand name: context engineering. Most "the agent got dumber" bugs are packing bugs, not model bugs.

Safar ke liye packing ek hunar hai: jo chahiye woh lo, roz ki cheezein aise rakho ki aasaani se mil jaayein, aur baaki ghar chhod do. Haron ki diary pack karna bhi yahi hunar hai, aur iska bhaari naam hai: context engineering. "Agent bewakoof ho gaya" wale zyaadatar bugs packing ke bugs hain, model ke nahi.

1

The packing orderPacking ka order

Remember the train from Chapter 1: the prompt cache reuses the front of the request only while it stays exactly the same. So we pack from never-changing to always-changing.

Chapter 1 ki train yaad karo: prompt cache request ka aage ka hissa tabhi reuse karta hai jab woh bilkul same rahe. Isliye hum kabhi-na-badalne-wale se hamesha-badalne-wale ki taraf pack karte hain.

2

Fetching the right pages (RAG)Sahi pages laana (RAG)

Acme has hundreds of HR policies. Putting all of them in the diary is slow, costly and makes Haron miss details. Instead, the team searches the library for the pages that match the question and packs only those. This is retrieval-augmented generation (RAG).

Acme ki saikadon HR policies hain. Sabko diary mein daalna slow, mehenga hai aur Haron details miss karta hai. Iske badle team library mein sawaal se match karne wale pages dhoondhti hai aur sirf wahi pack karti hai. Ise retrieval-augmented generation (RAG) kehte hain.

AI behaviour

More context can make answers worseZyaada context jawab bigaad bhi sakta hai

Ten retrieved pages where one is relevant often beat zero pages, but lose to two good pages. Irrelevant text distracts the model and can even pull it towards a wrong but similar-looking answer. Retrieve fewer, better pages, and put the best one closest to the question.

Das pages jinme ek hi kaam ka ho, aksar zero pages se behtar hain, par do achhe pages se haar jaate hain. Bekaar text model ka dhyaan bhatkaata hai aur use milte-julte galat jawab ki taraf kheench sakta hai. Kam par behtar pages laao, aur sabse achha page sawaal ke sabse paas rakho.

3

Squeezing the past (compaction)Purani baatein dabaana (compaction)

Haron is auditing 30 expense reports. After 91 messages, the diary is too thick. The team keeps the original task and the last few messages word for word, and replaces everything in between with a short summary. One rule: never separate a tool call from its result.

Haron 30 expense reports audit kar raha hai. 91 messages ke baad diary bahut moti ho gayi. Team asli kaam aur aakhri kuch messages jaise ke taise rakhti hai, aur beech ka sab ek chhote summary se badal deti hai. Ek niyam: tool call ko uske result se kabhi alag mat karo.

Harness note

Progressive disclosureDheere-dheere kholna

Don't load 200 skill manuals up front. Put a one-line index of skills in the system prompt ("gst-return: filing GST returns"), and let Haron read the full manual with a tool only when the task needs it. Claude Code's skills and many enterprise harnesses work this way. It keeps the stable prefix small and cache-friendly.

200 skill manuals pehle se load mat karo. System prompt mein skills ka ek-line index rakho ("gst-return: GST return file karna"), aur Haron tool se poora manual tabhi padhe jab kaam ko zaroorat ho. Claude Code ki skills aur kai enterprise harness aise hi chalte hain. Isse stable prefix chhota aur cache-friendly rehta hai.

Enterprise

Retrieval must respect permissionsRetrieval ko permissions ka dhyaan rakhna hoga

If the search index contains salary files, a clever question can pull them into an intern's chat. Filter retrieval by the caller's access rights (document ACLs) before ranking, not after. Long-term memory needs the same care: what is remembered, for how long, and who can ask the agent to forget it (DPDP and GDPR give people that right; Chapter 12).

Agar search index mein salary files hain, toh chalaak sawaal unhe intern ki chat mein kheench sakta hai. Ranking se pehle retrieval ko poochne wale ke access rights (document ACLs) se filter karo, baad mein nahi. Long-term memory mein bhi yahi dhyaan: kya yaad rakha jaata hai, kitne samay tak, aur kaun agent se bhoolne ko keh sakta hai (DPDP aur GDPR logon ko yeh haq dete hain; Chapter 12).

Deep dive: BM25, embeddings and hybrid searchGehraai mein: BM25, embeddings aur hybrid searchadvanced
BM25(q, d) = Σw∈q IDF(w) · f(w,d)(k₁+1) / ( f(w,d) + k₁(1 − b + b·|d|/avgdl) ) (8.1)

BM25 scores keyword overlap, weighting rare words more. It is fast, explainable and strong on exact terms (policy names, error codes). Embedding search turns text into vectors (Chapter 1's meaning map) and finds neighbours, which is good for paraphrases. Production systems often use hybrid search (both, merged with reciprocal-rank fusion), then a reranker model on the top 20–50, then keep the top 3–5. Chunk documents by meaning (headings, paragraphs), keep a source ID on every chunk, and evaluate retrieval separately from generation: recall@k tells you whether the right page was even found.

BM25 keywords ke mel ko score karta hai, rare words ko zyaada weight dekar. Yeh tez, samjhaane laayak aur sateek shabdon (policy naam, error codes) par majboot hai. Embedding search text ko vectors (Chapter 1 ka meaning map) mein badalkar padosi dhoondhta hai, jo alag shabdon mein kahi same baat ke liye achha hai. Production systems aksar hybrid search (dono, reciprocal-rank fusion se mila kar) use karte hain, phir top 20–50 par reranker model, phir top 3–5 rakhte hain. Documents ko matlab ke hisaab se kaato (headings, paragraphs), har chunk par source ID rakho, aur retrieval ko generation se alag evaluate karo: recall@k batata hai ki sahi page mila bhi ya nahi.

Yahan summariser extractive hai (har purane message ke pehle kuch characters rakhta hai) taaki offline chale. Production mein summary ek chhote, saste model se likhwao, aur batao kya bachna zaroori hai: faisle, khule sawaal, IDs, file paths aur errors.

✓

What we learnedHumne kya seekha

  1. Pack my diary from never-changing to always-changing.
  2. Fetch a few good pages, not the whole library, and filter by who is asking.
  3. When the diary gets thick, summarise the middle; keep the task and recent steps.
  4. Load skill manuals only when the task needs them.
  1. Meri diary kabhi-na-badalne-wale se hamesha-badalne-wale ki taraf pack karo.
  2. Poori library nahi, kuch achhe pages laao, aur poochne wale ke hisaab se filter karo.
  3. Diary moti ho toh beech ka summary banao; kaam aur haal ke steps rakho.
  4. Skill manuals tabhi load karo jab kaam ko zaroorat ho.
